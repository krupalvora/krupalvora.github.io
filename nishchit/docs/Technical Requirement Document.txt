PRD: Post-Chart Seat Finder (Indian Railways)
Nov 21, 2026 · @Krupal Vora
Summary
Verdict: the pain is real, but the product as briefed already exists. IRCTC has shown segment-wise vacant berths since Feb 2019, and GapSeat already does seat hopping on top of that data. Build it only if it does what neither does today.
What the revised product does differently:
• Input: 1 field (paste a PNR) or 2 fields (from city, to city), down from 4. Train, date, class and station all default.
• Timing: the app watches the trip and alerts when the first chart lands, then rechecks at the second chart. The user never has to check at the right minute.
• Search scope: every train on the corridor, every class, nearby boarding and alighting stations. Not one train at a time.
• Output: a bookable plan, not a seat list: legs, coach and berth, where to switch, total fare, and a booking handoff per leg.
• Before chart: a historical vacancy score per train and segment, so users know if waiting is worth it.
Biggest risk: data access. There is no public IRCTC API for chart data, so launch needs written permission or a licensed source (see Data sources).
Fact check of the original problem statement
The core mechanism holds: berths free up by segment, and stitching segments gets people seated. Five assumptions in the brief are wrong or outdated, and two of them change the product.

With no confirmed seat, the user can still board on a waiting ticket
No longer true. Waitlisted tickets, online or counter, are not valid in sleeper or AC coaches. Fines run Rs 250 (SL) to Rs 440 (AC) plus deboarding. Online WL e-tickets are auto-cancelled and refunded at chart (Zee News, IRCTC FAQ via FabHotels)
Every plan must end in a confirmed ticket bought through current booking. "Board and hope" is not a valid outcome.
The chart is prepared 4 hours before departure
Changed twice: 8 hours (Jul 2025), then 10 hours (Dec 2025). Trains leaving 05:01 to 14:00 get their first chart by 20:00 the previous day. The second chart comes 30 to 5 minutes before departure (Hitavada, Oneindia, ThePrint)
The window to act is now 10+ hours. Alerts at chart time become the core feature.
Each station pair has a fixed quota (A to B 100, A to C 100, B to C 50)
Simplified. Seats are split by quota type (General, Tatkal, Ladies, Senior Citizen, Pooled, Remote Location and others), not per station pair. Segment gaps come from where passengers board and alight, quotas released unused at chart, and cancellations before chart.
Don't model quotas. Read the chart berth by berth, segment by segment.
Users cancel after the chart, so seats free up
E-tickets can't be cancelled after chart; refunds go through TDR (etrain FAQ). After the second chart, leftover berths move to the next remote location or are allotted on board by the TTE.
Rescan at the second chart. After departure, switch to an on-board view for the TTE conversation.
The user has no option when tickets are unavailable
IRCTC Chart Vacancy shows vacant and partly booked berths coach-wise, with no login (PIB). Current booking sells them after the first chart (NewsX).
The gap is discovery and stitching, not missing information.
One more correction: the brief's "chart" URL is the public Charts/Vacancy page. It is a browser front end, not a published API.

Revised problem statement
A traveller with no confirmed berth has no easy way to learn, in time, that a seated journey is possible by combining partial vacancies, and no fast way to book it.
Why it happens:
• Busy trains show deep waitlists yet run with berths empty on parts of the route, because passengers board and alight at different stations and quotas are released at chart.
• Those berths become bookable through current booking only after the first chart, a moment the user has to catch manually.
• Finding a usable combination means knowing the train number, reading a coach map segment by segment, then booking each leg separately before the second chart closes the window.
• Since 2025, a waitlisted ticket is no fallback: it is invalid in reserved coaches.
Who loses: the passenger, who pays for a bus or flight or drops the trip, and Railways, whose berths run empty on segments.
Open question: how many berth-segments go empty per train is not published. The pilot must measure it on 20 to 30 busy trains before scaling.

Recommendation engine
The engine treats each berth as a set of vacant station intervals and finds the cheapest path from origin to destination. One train's chart solves in milliseconds; a corridor of 30 trains stays well under the 3 s budget.
Data model
• Route: ordered stations S0 to Sn, with arrival, departure and halt minutes.
• Berth: train, class, coach, number, type.
• Vacancy: per berth, the station intervals [i, j) where it is free, from the chart.
• Query: origin index o, destination index d, party size k.
Algorithm
1.  Full journey: any berth whose free interval covers [o, d). Linear scan.
2.  Fewest switches: greedy interval cover. From the current station, take the free interval that reaches furthest; repeat until d or no progress. Proven minimum legs.
3.  Best plan: shortest path over stations. Each free interval is an edge; cost = switch weight plus penalties below. Return the top 3 distinct plans.
4.  Partial: if d is unreachable, return the plan reaching the furthest station, and the latest boarding station from which d is reachable.
5.  Groups: every leg needs k berths; switch stations are shared by the whole party.
legs = []; c = o
while c < d:
    best = max(free intervals with start <= c, key = end)
    if best is None or best.end <= c: return partial(legs, c)
    legs.append(best.clip(c, d)); c = best.end
return legs
Ranking, in priority order
1.  Fewer switches.
2.  Safe switches: halt of 5 min or more, not between 23:00 and 06:00.
3.  Short walks: same or adjacent coach at each switch.
4.  Lower total fare. Each leg is a separate ticket with its own reservation charge, so show the cost above a through ticket.
5.  Berth type: lower, then middle, then upper; side berths last on legs over 6 hours.
Fallback ladder shown to the user
1.  Same train and class, one berth, full journey.
2.  Same train and class, up to 2 switches.
3.  Same train, another class.
4.  Station flex: board earlier or alight later within the city cluster.
5.  Other trains on the corridor, repeating steps 1 to 4.
6.  Change trains at a junction (P1).
7.  Partial plan to the furthest station, with the uncovered distance in km.
Data sources, legal and compliance
Data access is the gating risk: the Charts/Vacancy page is public, but it is a website, not a licensed feed, and IRCTC's terms govern how it is used. No public launch until one of the routes below is cleared by a lawyer.
Routes to the chart data, in order of preference
1.  Authorised access: approach IRCTC and CRIS for a chart vacancy feed. IRCTC already licenses B2B partners and travel aggregators under agreements, so a data partnership is a known shape.
2.  A licensed third-party provider that holds redistribution rights.
3.  Closed beta only: on-demand fetches for named watched trips, heavy caching, low request rate, no resale. Stop on any objection.
Other data
• Train routes, timetables and station clusters: static, refreshed weekly.
• Fares: computed per leg from the fare table; shown as an estimate until IRCTC confirms.
• PNR status: same access question as charts; treat it under the same route.
Compliance
• Store berth status only. Never store passenger names or other people's booking details.
• PNRs are personal data under the DPDP Act 2023: explicit consent, encrypted at rest, deleted 7 days after the journey.
• Never ask for IRCTC login credentials.
• WhatsApp alerts are opt-in, on approved message templates.
• State on every screen: not affiliated with IRCTC or Indian Railways; a plan is not a ticket.
Booking rules to verify before launch
• Current booking cut-off when a leg starts at an intermediate station.
• Whether one passenger may hold several current tickets on the same train for back-to-back legs.
• Whether a berth vacant at chart can still be bought for a single intermediate segment online, or only at the counter.

Appendix: the original brief, polished
Your brief, kept close to its structure and wording with the facts corrected. The sections above supersede it.
Product: a web app that shows which seats are still available on a train after the reservation chart is prepared.
Problem: When a passenger wants to travel from A to B and no confirmed seats are left, booking sites offer only a waitlist. A waitlisted ticket no longer allows travel in a reserved coach, so in practice the passenger has no option. Yet trains rarely run full end to end. Passengers board and alight at different stations, unused quotas are released at chart time, and some tickets are cancelled before it. Many berths are therefore free for part of the route. By moving between berths at intermediate stations, a passenger can often get a seat for the whole journey or most of it, and Railways fills capacity that would otherwise run empty.
Solution: Once the first chart is published (about 10 hours before departure, or by 20:00 the previous day for trains leaving 05:01 to 14:00), read the train's vacancy data from IRCTC's Charts/Vacancy page. The user enters train number, date, boarding station and destination. The app returns, in order of preference:
1.  A single berth vacant for the whole journey, with coach and berth number.
2.  Otherwise, the combination of berths that covers the whole journey with the fewest switches.
3.  Otherwise, a plan that gets as close to the destination as possible.
The passenger books each berth through IRCTC current booking before the second chart, prepared 30 to 5 minutes before departure. Late changes appear only in the second chart, so the app checks it again.
